# Tests

**Last modified:** 2026-08-11

## Purpose
Unit and integration tests for the doc-sync guard. The pure helpers (CONTEXT.md parsing, LOG.md timestamp parsing, ownership resolution, and diff parsing) are exercised with fixtures; the end-to-end behaviour is exercised against real throwaway git repositories built in a temp directory, so scope collection, ownership, and the mtime-based LOG check run the way they do for real. The output-inventory tests run against the real repository, because the inventory describes this project and a fixture copy of it would only prove the fixture was self-consistent; the one exception builds a throwaway repo carrying the `.gitignore` with the stage's block stripped out, so "these paths were not ignored before" is measured rather than remembered.

## Contents
- test_doc_sync_guard.py - `workflows/doc-sync-guard/tests/test_doc_sync_guard.py` [[workflows/doc-sync-guard/tests/CONTEXT]] - Tests for `context_parse` (Last modified, Revision History dates, archive-line skipping, bracketed-entry counting, and the section-aware `gained_rh_entry` including the same-day second-entry, dated-bullet-outside-the-section, edited-entry-date-forward, edited-entry-text, flat-count archive-plus-add, indented-sub-bullet, and reorder-edit-with-fake-archive cases), `logtime` (newest entry, legacy date-only, behind/tolerance/ahead), ownership and diff parsing (`owner_dir`, `committable_context_dirs`, `deleted_context_dirs`, `path_under_dir`, `_parse_name_status`), and the integration scenarios (clean pass, CONTEXT not updated, missing Revision History entry, editing an old entry forward flagged, Last modified mismatch, same-day edit pass, untracked coverage, new-directory-owns-itself, parent propagation, move between two documented directories flagging both source and destination, removed child directory flagging the parent without an impossible deleted-child warning, git failure surfacing as WARN, LOG behind, trailing source edit after the LOG entry, deleted-file skip, missing LOG, gitignore carve-out, the `--json` contract, staged mode, and staged-blob reads under a divergent working tree), plus `ContextOnlyOwnerTest` for a directory whose only changed file is its own CONTEXT.md (a positive control per clause, the two recording-mode controls, and a negative control).
- test_output_paths.py - `workflows/doc-sync-guard/tests/test_output_paths.py` [[workflows/doc-sync-guard/tests/CONTEXT]] - Tests for the classified output inventory and its loader: the guard output paths asserted either side of the `.gitignore` block that protects them, every inventory row asserted against the real repository with `git check-ignore`, the schema refusals (the seven key-set cases individually, the doc-sync / provenance / assertion / version value sets, duplicates and unknown keys), fail-closed behaviour on a missing or malformed config, the loader's answers (E13, the launcher rows, derived signature exclusion, the unmatched-path default, out-of-scope rows being seed-only), the documented-child fixture that a prefix matcher fails, the personal-container predicate over every path and example with its two must-fail fixtures, the single-consumer check, `run.py` importing under an interpreter with PyYAML blocked, the severity of the inventory degrade (DEGRADED and never WARN, asserted per finding), which import failures may degrade (a blocked PyYAML with the loader dropped from the module cache degrades; any other import failure propagates), the `strict_failed` gate over each severity combination, and the report rendering for a degrade-only run.
- run_tests.py - `workflows/doc-sync-guard/tests/run_tests.py` [[workflows/doc-sync-guard/tests/CONTEXT]] - One-command unittest discovery runner; bootstraps into the project `.venv` so the inventory tests have PyYAML, and exits non-zero on any failure.

## Inputs
- The guard modules at `workflows/doc-sync-guard/scripts/` [[workflows/doc-sync-guard/scripts/CONTEXT]], imported directly.
- The `git` CLI, used to build the throwaway repositories the integration tests run against.

## Outputs
- Test results on stdout. Exit 0 when all pass, 1 otherwise. No project files written (temp repositories are created under the system temp directory and cleaned up).

## Steps
1. Run `python workflows/doc-sync-guard/tests/run_tests.py`.
2. All tests must pass before the work is considered ready.

## Dependencies
- `workflows/doc-sync-guard/scripts/run.py` [[workflows/doc-sync-guard/scripts/CONTEXT]] and its `context_parse`, `logtime`, and `inventory` helpers - the modules under test.
- `workflows/doc-sync-guard/config/output-inventory.yaml` [[workflows/doc-sync-guard/config/CONTEXT]] and the project `.gitignore` - the data the inventory tests assert against.
- The `git` CLI - the integration tests build real repositories and the inventory assertions call `git check-ignore`; without git those tests cannot run.
- Python 3.9+ standard library (`unittest`, `tempfile`, `subprocess`), plus PyYAML from the project `.venv` for the inventory tests.

## Known Issues
- The integration tests shell out to `git` and create temp repositories, so they are slower than the pure-helper tests and require git on PATH.
- The inventory assertions read the real repository, so they are a check on this project rather than on the loader alone. That is deliberate (the inventory's whole claim is about this repository), but it does mean a `.gitignore` edit can fail the guard's own suite, which is the intended signal rather than a flake.

Found by Codex's review of stage 3A; the writes were invisible until `encoding-guard` was taught to check the newline clause independently of the encoding one. Test count unchanged at 121: this is a fixture-mechanism change with no assertion touched.
