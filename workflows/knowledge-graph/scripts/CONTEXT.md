# Knowledge Graph — Scripts

**Last modified:** 2026-08-04

## Purpose
Holds the Python implementation of the knowledge-graph indexer: the tolerant CONTEXT.md parser, the node/edge graph model with atomic serialisation plus adjacency and traversal, the gitignore-aware builder that resolves relationships into edges, the opt-in content layers (memory, wiki, journal, and conversation) with their shared parsing helpers, the validation checks, the shared report formatter, shared constants and path helpers, and the run.py command-line entry point.

## Contents
- run.py — `workflows/knowledge-graph/scripts/run.py` [[workflows/knowledge-graph/scripts/CONTEXT]] — Command-line entry point. Provides `build` plus the read-only `validate`, `node`, `neighbors`, `impact`, `path`, `subtree`, `stats`, `orphans`, `broken`, and `sessions` subcommands (all with `--json` and the opt-in, repeatable `--layer memory`/`--layer wiki`/`--layer journal`/`--layer conversation` flag). The `sessions <id>` command is a read-only, best-effort cross-reference — it derives FTS5 search terms from a node (the `session_query_terms` helper: node title, fallback to the last id segment, sanitised) and shells out to the session-search `search.py --json` via the `run_session_search` wrapper to list the transcripts that mention the node; an absent or unreadable index yields no sessions, never an error, and nothing is persisted.
- builder.py — `workflows/knowledge-graph/scripts/builder.py` [[workflows/knowledge-graph/scripts/CONTEXT]] — Walks the project (breadth-first, pruning skip/hidden/gitignored/no-recurse directories before descending; one batched `git check-ignore` per depth level, skipped entirely outside a Git worktree), parses each CONTEXT.md and root file, resolves and types nodes and edges, returns a Graph. Calls the memory layer when `build_graph(include_memory=True)`, the wiki layer when `build_graph(include_wiki=True)`, the journal layer when `build_graph(include_journal=True)`, and the conversation layer when `build_graph(include_conversation=True)`.
- parser.py — `workflows/knowledge-graph/scripts/parser.py` [[workflows/knowledge-graph/scripts/CONTEXT]] — Tolerant CONTEXT.md parser; extracts title, last modified, sections, per-section backtick tokens, and links. Never raises.
- content_layer.py — `workflows/knowledge-graph/scripts/content_layer.py` [[workflows/knowledge-graph/scripts/CONTEXT]] — Shared, pure parsing helpers for the opt-in content layers: fenced-code stripping, order-preserving dedupe, and `[[link]]`/backtick extraction. Imported by memory.py, wiki.py, journal.py, and conversation.py so no layer owns another's parsing code.
- memory.py — `workflows/knowledge-graph/scripts/memory.py` [[workflows/knowledge-graph/scripts/CONTEXT]] — Opt-in Phase 5 memory layer: a stdlib frontmatter reader plus memory node/edge construction (memory `[[links]]`, MEMORY.md membership, and memory→structural cross-references), reusing the content_layer helpers. Invoked only when `build` is given `--layer memory`; never alters the structural graph.
- wiki.py — `workflows/knowledge-graph/scripts/wiki.py` [[workflows/knowledge-graph/scripts/CONTEXT]] — Opt-in Phase 6 wiki sub-graph layer: indexes each wiki's internal pages (the per-wiki `wiki/` folder under `wikis/` [[wikis/CONTEXT]]) as namespaced `wiki-page` nodes (path-as-id), resolves intra-wiki `[[stem]]` links per-wiki (cross-wiki links stay INFO), adds wiki→structural references and per-wiki membership edges. Invoked only when `build` is given `--layer wiki`; never alters the structural graph.
- journal.py — `workflows/knowledge-graph/scripts/journal.py` [[workflows/knowledge-graph/scripts/CONTEXT]] — Opt-in Phase 7 journal (light) layer: indexes each `journal/entries/YYYY-MM.md` month file as a `journal-entry` node (path-as-id, title from the `# Journal — …` heading), with its outbound `[[links]]` (resolved within the journal layer then structurally), backtick journal→structural references, and `contains` membership edges from the `journal/entries` [[journal/entries/CONTEXT]] directory node. Deliberately light — most months produce a node and few or zero edges. Invoked only when `build` is given `--layer journal`; never alters the structural graph.
- conversation.py — `workflows/knowledge-graph/scripts/conversation.py` [[workflows/knowledge-graph/scripts/CONTEXT]] — Opt-in Phase 8 conversation layer: indexes the gitignored saved conversations under `conversations/` [[conversations/CONTEXT]] — standalone `*.md` files directly under `conversations/` as `conversation` nodes and each doc-set subdirectory's pages as namespaced `conversation-doc` nodes (path-as-id, per-doc-set `[[stem]]` resolution that keeps cross-namespace links INFO) — with conversation→structural `[[link]]`/backtick references and `contains` membership from the tracked `conversations` directory node. Invoked only when `build` is given `--layer conversation`; never alters the structural graph.
- graph.py — `workflows/knowledge-graph/scripts/graph.py` [[workflows/knowledge-graph/scripts/CONTEXT]] — Node and Edge dataclasses, the Graph container with edge de-duplication, deterministic serialisation, atomic JSON writing, a `from_dicts` loader, lazy adjacency indexes, and cycle-safe traversal (reverse reachability, shortest path, subtree).
- validate.py — `workflows/knowledge-graph/scripts/validate.py` [[workflows/knowledge-graph/scripts/CONTEXT]] — Six validation checks (broken-reference classification, orphans, descendant-aware uncontained directories, duplicate titles, parse warnings, dependency back-reference gaps) producing audit-style findings. Content-layer-sourced unresolved edges (memory, wiki pages, journal entries, and conversations) classify INFO (forward references), never WARN.
- report.py — `workflows/knowledge-graph/scripts/report.py` [[workflows/knowledge-graph/scripts/CONTEXT]] — Finding dataclass, FAIL/WARN/INFO Markdown report formatter mirroring the audit report, and the exit-code rule.
- common.py — `workflows/knowledge-graph/scripts/common.py` [[workflows/knowledge-graph/scripts/CONTEXT]] — Shared constants (skip dirs, top-level dirs, root files), path helpers, timestamp, and safe file reading.

## Inputs
None directly. The scripts read the project structure relative to the project root. The `--from-index` query flag additionally reads the saved `index/*.json`.

## Outputs
- `index/nodes.json`, `index/edges.json`, `index/meta.json` written by run.py build.
- A validation report printed to stdout, optionally saved to `workflows/knowledge-graph/last-report.md` via `validate --save` (gitignored).
- LOG.md entries (workflow and root) on a real `build` or `validate` run. Pure read-only query commands do not log.

## Steps
1. `run.py build` calls `builder.build_graph()` to construct the graph from the project tree. With `--layer memory` it passes `include_memory=True` (memory layer via `memory.add_memory_layer`); with `--layer wiki` it passes `include_wiki=True` (wiki sub-graph layer via `wiki.add_wiki_layer`); with `--layer journal` it passes `include_journal=True` (journal layer via `journal.add_journal_layer`); with `--layer conversation` it passes `include_conversation=True` (conversation layer via `conversation.add_conversation_layer`). The flags are repeatable and combine; the included layers are recorded in `meta.json`.
2. The resulting Graph is serialised deterministically and written atomically to `index/` via `graph.atomic_write_json`.
3. `run.py validate` rebuilds the graph in memory (or loads it with `--from-index`), runs `validate.run_checks`, and prints a `report.format_report` summary.
4. Query commands (`node`/`neighbors`/`impact`/`path`/`subtree`/`stats`/`orphans`/`broken`) rebuild the graph and traverse it; unknown ids produce a difflib-suggested error.
5. A summary is printed; started/completed entries are appended to LOG.md (skipped on `--dry-run` and on read-only queries).
6. Append LOG.md with a completion or failure entry.

## Dependencies
- `AGENTS.md` [[AGENTS]] (root) — Defines the CONTEXT.md schema the parser targets.
- Python 3.9+ standard library only (re, json, os, subprocess, pathlib, dataclasses, collections, difflib).
- `workflows/session-search/scripts/search.py` [[workflows/session-search/scripts/CONTEXT]] — Runtime dependency of the `sessions` command only, invoked as a subprocess (`search.py --json`), never imported. If it is missing or fails, `sessions` degrades to an empty result set; no other command depends on it.
- `git` (optional) — for gitignore-aware pruning in builder.collect_dirs and for the broken-reference gitignore classification in validate; falls back gracefully when absent (refs then classify as genuine).

## Known Issues
- The memory, wiki, journal, and conversation layers read gitignored content directly (`memory/` files, `wikis/<name>/wiki/` pages, `journal/entries/YYYY-MM.md` month files, and the `conversations/` [[conversations/CONTEXT]] standalone files and doc-set pages; the `--layer memory`/`--layer wiki`/`--layer journal`/`--layer conversation` flags are the deliberate opt-in), so their node titles are personal content and only ever land in the gitignored `index/` and `last-report.md`. Never widen what is tracked.
- The conversation layer roots all `contains` membership at the single tracked `conversations` directory node — for both standalone files and doc-set pages — rather than at a per-doc-set node like the wiki layer. A `conversations/<doc-set>` node would be a plain `directory` type with no inbound edge (the doc-sets are deliberately not listed in `conversations/CONTEXT.md` [[conversations/CONTEXT]] under personal-data isolation), so creating one would surface a WARN orphan. Doc-set `[[stem]]` resolution is still per-set namespaced; only membership is centralised.
- The journal layer is light by design: real month files are plain daily prose and usually carry no `[[links]]` and no backtick project paths, so a month typically produces just a node tied to `journal/entries` [[journal/entries/CONTEXT]] by membership. Zero outbound edges is expected, not a bug.
- Wiki `[[stem]]` link resolution is exact (case-sensitive), matching the memory layer. A link whose case differs from the page filename (e.g. `[[Lists]]` for `lists.md`) is left as an INFO forward reference rather than resolved, so it is visible but not silently linked. This is by design; Obsidian itself is case-insensitive, so revisit only if case-folding becomes desirable.
- The builder reuses the audit workflow's proven `os.walk` + `git check-ignore` pruning approach but does not import from it, to keep the indexer self-contained. If the audit pruning logic changes meaningfully, consider keeping the two in sync.
- Validation and query commands rebuild the graph in memory by default (sub-second) to avoid stale-index answers; `--from-index` trades freshness for speed against the saved JSON.
- The dependency back-reference gap check (`validate` check 6) is advisory (INFO) and can be skipped with `--no-backrefs`.
- The `sessions` command is best-effort and FTS5 keyword-based (not semantic): it matches the node's title/derived terms against transcript text, so a node never discussed returns nothing, and term quality depends on the title. It returns personal session data (titles, snippets) to the caller at query time only — never written to any tracked file and never merged into the structural audit. An absent/unreadable session index, a missing or crashing `search.py`, or unparseable output all yield an empty result and exit 0; the per-shard FTS5 errors that `search.py` may hit are sent to its stderr so the JSON contract on stdout stays clean.
