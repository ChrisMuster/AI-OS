# Rule Hooks - Tests

**Last modified:** 2026-08-11

## Purpose
Synthetic-event tests for the rule-hooks evaluator: prove each rule blocks what it should and allows what it should (the false-positive guards), and prove each adapter parses its AI's payload and emits the right block contract. Verification discipline: the build is not done until the suite passes and a live block is confirmed.

## Contents
- test_rule_hooks.py - `workflows/rule-hooks/tests/test_rule_hooks.py` [[workflows/rule-hooks/tests/CONTEXT]] - The full suite (73 tests): per-rule block/allow cases via the in-process Context pipeline, adapter input-parsing tests, subprocess tests asserting the real output contracts (Claude exit 2 + stderr; Codex `hookSpecificOutput` JSON deny), `TestPrecommitDocSync` (the pre-commit doc-sync advisory: the pure `format_doc_sync_advisory` text, that a personal-data block short-circuits before the advisory, that a clean personal-data check runs the advisory and still allows the commit, and that a doc-sync guard crash is swallowed), `TestPrecommitDocSyncSeverity` (the advisory's severity filter: drift alone prints the advisory - the positive control - while a DEGRADED finding alone prints nothing and a degrade alongside real drift neither prints itself nor masks the drift), `TestPrecommitDocSyncRecording` (the collection path for the doc-sync guard's switched-off CONTEXT-only LOG clause: a fire records both counts, a fire with no findings records zeroes as the denominator, a degraded fire is recorded rather than dropped, a fire the personal-data gate blocks records nothing, the advisory still prints WARN only, the real guard writes no file during a fire over a throwaway repository carrying the case, a failing fire-log write costs a sample rather than a commit, and a source-level check that no test in this file reaches the fire-log write without redirecting `FIRE_LOG`), and `TestCwdIndependence` (the hook launches `run.py` from a project-root-anchored command, so evaluation must survive a drifted working directory: Claude invocations from a temp directory outside the repo still block a `.env` write and still allow a normal write; shipped `.claude/settings.json` hook commands anchor `run.py` to `$CLAUDE_PROJECT_DIR`; shipped `.codex/config.toml` hook commands resolve the git root; and a Codex hook command blocks from a project subdirectory). Destructive cases use safe synthetic strings only; the B3 detection email is assembled at runtime so the literal never appears in the committed source.

## Inputs
- None beyond the workflow scripts under test and the live git repo (the B3 gitignored-vs-committable test uses real `git check-ignore`).

## Outputs
- Test pass/fail results on stdout.

## Steps
1. Run: `python workflows/rule-hooks/tests/test_rule_hooks.py`
2. All tests must pass before the work is ready.

## Dependencies
- `workflows/rule-hooks/scripts/` [[workflows/rule-hooks/scripts/CONTEXT]] - The code under test.
- `workflows/personal-data-guard/` [[workflows/personal-data-guard/CONTEXT]] - Reached via the B3 rule in the personal-data tests.

## Known Issues
- The subprocess tests spawn `run.py`, so the suite shells out; it stays fast (about 2 seconds) because the evaluator is light at import time.
- **Any test that reaches `_precommit_doc_sync` must redirect `run_mod.FIRE_LOG` to a temp path.** That function appends a `doc_sync_recording` row, and the real fire-log is the store the recording-mode observation period counts, so a row written by a test is indistinguishable from a genuine sample reporting no findings. `test_no_test_writes_to_the_real_fire_log` enforces this at the source rather than at runtime, since a runtime check only catches whichever test happens to run.

Run against the unmodified collection path first, where four failed on the missing row; the other three pass on both sides by design, since what they pin is that recording mode changed nothing. 65 -> 72 tests.
- 2026-08-11 - Fixed a test-isolation defect the stage 14 commit introduced, found while running the producer proof rather than by the suite. `_precommit_doc_sync` gained a fire-log write, which turned the three pre-existing `TestPrecommitDocSyncSeverity` tests into producers: they call that function with a stubbed guard and had never needed to redirect `FIRE_LOG`, because until then the call had no side effect. Nine junk rows reached the real fire-log across three suite runs, three of them carrying `degraded: 0`, which the read would have counted as genuine samples reporting no findings and so biased the measurement toward enabling the clause. `FIRE_LOG` is now redirected in that class's `setUp`, and in `test_doc_sync_guard_crash_is_swallowed` as well even though its path returns before writing, so the rule has no exceptions to reason about. Added `test_no_test_writes_to_the_real_fire_log`, which walks this file's own parse tree and fails on any method reaching the write without a redirect, allowing only the two that mock `_precommit_doc_sync` itself. It was checked with two positive controls, a synthetic offender and this file with the severity class's redirect stripped, because a detector that only ever returns an empty list proves nothing; both were caught. The nine junk rows were removed from the fire-log with every other line preserved verbatim, leaving the single genuine row written by the stage 14 commit. 72 to 73 tests.
