# Review Orchestration - Tests

**Last modified:** 2026-10-28

## Purpose
Hermetic unittest suites for the review-orchestration scripts. The checker validates, so each rule carries up to three controls, named in the test names: a **positive control** (a legal instance, built from the specification, which must produce nothing), a **rejection control** (an illegal instance, which must be refused with its reason named) and a **negative control** (something that looks like the subject but is not an instance of it, such as an operator inside quotes, a heading inside a comment, or a dash line under a list item, which must not be refused for it).

## Outputs
- Test results on stdout, exit code 0 when all pass. Every other fixture is written into a temporary directory with `write_bytes`, so no CRLF is introduced on Windows. Nothing writes to the real `LOG.md` or the real `runs/`: in-process calls inject a temporary log path or runs folder and subprocess calls pass `--dry-run`.

## Steps
1. Run each suite, for example `python workflows/review-orchestration/tests/test_brief.py`, under the project `.venv` so the SDKs are present.
2. Confirm every test passes (exit 0) and that none was skipped on Windows. Off Windows, exactly one skip is expected (see Known Issues).
3. When a rule in a script changes, change or add its controls here in the same change.
4. Append LOG.md only when run as a deliberate, logged workflow step.

## Known Issues
- Nothing enforces the control naming. A test added without a control prefix is simply an unlabelled test, held to the convention by review alone.
- `TemplateTests` and `SmokeTests` read the real template, and `SettingsTests` the real settings file, so they depend on the tree rather than on a fixture. That is deliberate: the property being proved is about those files.
- Without the SDKs installed, the tests that need them are skipped, with the install instruction as the reason. A run where they were skipped has not proved the Codex reading or the B1 event; the test output reports the skip count.
- No test calls a live provider. The Codex response shape was confirmed live on 2026-09-25 by one `account/rateLimits/read` request with no model call, outside the suite.
- `test_providers.py` proves how the sessions handle what the SDKs send, not that the SDKs send it: the fakes replay the SDKs' own types, but the call sequence (connect, query and receive for Claude; a Codex thread's turn and its event stream) is modelled on the installed SDKs, not recorded from a live session. The live proof runs are where each pairing is proved against the real providers. For the Codex builder the fake's answers are the shapes the probes recorded on 2026-10-01 and 2026-10-02 (`hooks/list` rows, the thread reply, the hook-run notifications), and the built session's launch was run once against the live app-server with no model call; a turn is first run live in the proof run.
- The loop files, `test_approval.py`, `test_planning.py` and the two `test_plan_*.py` files share `loop_fixtures.py`, so a change to that harness can break every one of them. Since A3 chunk 3 a start enters the planning half; the build-loop suites reach their build through `start_built`, which records the planning half as done rather than running it, and a run at the approval pause in `test_approval.py` is made the same way, so the whole path is proved only in `test_plan_review.py` and `test_plan_wiring.py`.
- `test_planning.py` and the `test_plan_*.py` files prove the planning half's handling of what its sessions return, with fakes; that the real planner, synthesiser and plan-reviewer sessions keep the reviewers' lockdown rests on their being the reviewer classes, whose own tests are in `test_providers.py`, and on the proof run after chunk 3.
- No test proves that a real Codex sandbox refuses a write to the frozen folder, or that a real Codex runs the hook: both are probe results and live checks, not unit tests.
- `HookTests` and the self-test in `CodexBuilderTests` start the Python interpreter as a subprocess, about 0.1 seconds each; `TurnCheckTests` takes two real inventories of a temporary git project per builder turn.
- `test_positive_windows_spelling_is_folded` runs on Windows only, since a backslash is a folder separator only there; off Windows (the orchestrator's Linux check container) it is skipped. Its any-system half, case folding, is `test_positive_case_is_folded_on_any_system`, which runs everywhere.
- The link test in `EditTests` skips itself where the machine cannot create a symlink; a run that skipped it has not proved that a link pointing out of an edit path is refused.
- The `test_loop*.py` files prove the loop's handling of what the sessions return, not what the providers return: its fakes stand in for `providers.py`'s session objects, whose own tests cover the SDK side. The live proof run is where the whole run meets both providers. `PacketTests` loads the real handoff reader from `workflows/handoff/scripts/` [[workflows/handoff/scripts/CONTEXT]], and the whole-run tests need the `git` CLI.
