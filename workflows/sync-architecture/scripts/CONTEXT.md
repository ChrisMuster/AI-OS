# Scripts

**Last modified:** 2026-08-27

## Purpose

Holds the sync architecture workflow's entry point and the selection rule it checks.
`run.py` carries both checks: the allowlist check, which extracts the fenced
classification block from the architecture plan and proves what it selects against the
real working tree, and the consistency check, which scans both design documents for the
named defect classes and measures each document against the version last reviewed.
`allowlist.py` holds the selection itself, in one copy, because `run.py` and the Stage A
build both need it and a check that resolves the pathspecs differently from the build is
not checking the build.

`run.py` is read-only and needs neither `--dry-run` nor idempotency handling.
`allowlist.py` is read-only except under `--stage`, which force-adds the selection into
the personal repository's index; that path takes `--dry-run` and is idempotent, since
re-adding an already-tracked file is a no-op. Standard library plus the git CLI only,
with no shell pipeline, so both run wherever Python does.

## Contents

- run.py - `workflows/sync-architecture/scripts/run.py` [[workflows/sync-architecture/scripts/CONTEXT]] - The entry point. `check_allowlist` resolves the classification through `allowlist.select`, then asserts positive controls (properties that must be true of the selection), category sweeps (kinds that must not appear), the invariant that no file is both publicly tracked and ignored, and the no-overlap rule measured on the uncorrected selection where it can actually fail. A positive control is kept no broader than the claim it backs: the three audit trails inside derived folders are asserted one at a time rather than as any-of-three, since an any-of control passes while two of the three are missing, and they are named by path because they are fixed locations the workflows maintain themselves rather than personal content. Where narrowing a control would mean naming a personal file, the answer is a fixture in the test suite instead, which tests the rule rather than the tree; `check_consistency` applies the documentary rules and the baseline hash comparison; `main` runs both by default and exits non-zero on any failure. `extract_planned` reads a fenced planned-artefacts block naming the scripts a stage has yet to create, and `unresolved_scripts` reports any script path a plan names that neither exists in the tree nor appears in that block. That pair is the general form of a defect the earlier rule caught only by its historical filename: a named script absent because it was never written reads exactly like one a stage has yet to build, and the declaration is what makes the difference checkable. An absent block yields an empty set, so nothing is exempt; reading it as a blanket exemption would let deleting the block disable the check silently. `compare_to_baseline` classifies a plan against its review baseline: a missing baseline is a failure, because that is the one state with no diff surface at all, while drift is reported as information with a real added/removed count from `difflib`. Drift is normal for most of an item's life, since the baseline holds the last-reviewed version and is refreshed only once a review round finishes. It re-exports `extract_block` from `allowlist` rather than carrying its own parser, so there is one copy. A `None` from the selection means git could not answer, and the caller degrades to SKIPPED rather than treating an unanswered question as a pass.
- allowlist.py - `workflows/sync-architecture/scripts/allowlist.py` [[workflows/sync-architecture/scripts/CONTEXT]] - The single executable copy of the selection rule, imported by `run.py` and called by the Stage A build. `extract_block` and `read_specs` pull the pathspecs out of the plan's fenced block so the document stays the authority. `shadow_selection` resolves them in the personal repository's git context, defaulting to a throwaway empty repository, which is the state the real one is in immediately before its seed commit. `public_tracked` and `tracked_and_ignored` measure the public repository; the latter passes `--no-index`, without which git refuses to report a tracked path as ignored and the check could never produce the finding it exists for. `select` returns the raw selection, the overlap, and the corrected set. `tracked_by_both` answers the separate post-seed question of whether one path sits in both repositories' indexes, which only becomes answerable once the personal repository has commits; it exists in Python rather than as a `comm` pipeline because that comparison is a set intersection and `comm` is absent from PowerShell. `stage` force-adds it in length-bounded batches, sized for the Windows command-line limit, and surfaces git's own stderr on failure rather than returning a bare `False`. `self_test` builds a tree containing a tracked-and-ignored file and asserts the two contexts disagree about it.

## Inputs

- `SYNC-ARCHITECTURE-PLAN.md` and `SHADOW-REPOSITORY-PLAN.md` at the project root, plus their `CODEX-*` review baselines. All are gitignored design-time documents, so all may be absent.
- A working `git`. Read-only for `run.py` and for `allowlist.py` in every mode except `--stage`.
- For `allowlist.py --stage`, the path to the personal repository's git directory.

## Outputs

- A human report on stdout, grouped FAIL / SKIP / PASS / INFO, and an exit code. `run.py` writes no files.
- `allowlist.py --stage` writes to the personal repository's index only: never the working tree, never the public repository. `--dry-run` prints the same selection and writes nothing.

## Steps

1. Parse arguments: `--check` (default), `--allowlist`, or `--consistency`.
2. For the allowlist check, read the plan and extract the fenced classification block; report FAIL if the block is missing or empty, since the check is meaningless without an authority to read.
3. Resolve the block's pathspecs through `allowlist.select`, in the personal repository's git context, and subtract the public repository's tracked set.
4. Assert each positive control and each category sweep against the corrected selection.
5. Assert the invariant that no file is both publicly tracked and matched by an ignore rule, then the no-overlap rule against the uncorrected selection, then that the subtraction removed them.
6. For the consistency check, apply the documentary rules to each design document, verify that every script path either document names exists in the tree or is declared in the architecture plan's planned-artefacts block, and measure each document against its review baseline through `compare_to_baseline`.
7. Print the grouped report and return 1 if any finding is FAIL, otherwise 0.
8. Append LOG.md with a completion or failure entry.

## Known Issues

- The baseline comparison cannot tell a correctly-timed refresh from a wrongly-timed one, because nothing in the tree records when a review round finished. It reports the drift and states the rule; the timing is a human judgement. A baseline refreshed mid-correction therefore reads as "no changes since the last review round", which is true of the files and false of the work.
- The superseded-spelling rule treats a mention of the old pattern as legitimate only when the corrected pattern appears on the same line, which is what makes a contrast sentence pass and a stale rule fail. A contrast split across two lines is therefore reported as a failure. That is deliberate: the false positive is cheap and visible, while the false negative is the defect the check exists to catch.
- Absence of a design document is reported as SKIPPED. A caller that treats SKIPPED as success gets no protection, which is why the summary line distinguishes "no failures" from "no failures, but N checks could not run".
- `run.py` imports `allowlist` by inserting its own directory on `sys.path`, so the two files must stay in the same directory. Moving one without the other breaks the import rather than degrading.
- The "corrected selection excludes tracked files" assertion is a regression guard on the subtraction step, not a property of the tree: it can only fail if that step is weakened or removed. It is labelled as such in the source so a future reader does not mistake it for evidence about the working tree.

## Revision History

- 2026-08-25 - Initial creation. Both checks existed first as throwaway scripts in a session scratchpad; giving them a tracked home is what makes the design documents' citation of them true. The allowlist assertions were rewritten from named files to structural properties on the way in, because a tracked file must not carry personal filenames and because a structural assertion keeps working when the underlying files change.
- 2026-08-26 - Added `allowlist.py` and rebuilt `run.py`'s allowlist check on top of it. The check had been resolving the classification pathspecs in public-repository context while the build resolves them with `--git-dir` and `--work-tree`, where "untracked" means untracked by the personal repository; the no-overlap assertion therefore could not fail, because public context strips every tracked file before the assertion looks for one. The selection, the subtraction that actually prevents the overlap, and the invariant beneath it now live in one module the check imports and the build calls. One defect was found and fixed while testing it: the staging helper discarded git's stderr, so a refused force-add printed nothing and read as a successful no-op.
- 2026-08-26 - Removed a `core.bare=false` argument from `stage` and the claim that went with it. A staging run had failed, the failure was attributed to the probe repository being bare, and the argument was added as the fix; the same entry recorded it as a defect found and fixed. Mutation-testing the new suite exposed the claim, because removing the argument changed nothing. Re-tested directly: `--work-tree` overrides `core.bare`, a bare probe accepts the force-add, and the real selection stages all 555 files without it. The original failure is not reproducible and was almost certainly the discarded-stderr defect hiding its own cause, which is the one real fix of the two. The property the verifier depends on is now asserted by a test rather than worked around.
- 2026-08-27 - Added `tracked_by_both` to `allowlist.py` and the script-declaration check to `run.py`, both found by simulating a Stage A build from the plans rather than by reading them. The first replaces a `comm` pipeline that the plan's own Stage A acceptance table used to check that no file is tracked by both repositories: `comm` is present in Git Bash and absent from PowerShell, so the stage's acceptance test was runnable on fewer of this project's AIs than the build step it checks. It is a genuinely different question from the one `select` answers, being about two indexes after the seed commit rather than about a pending selection, so it is a new function rather than a flag on an existing one. The second generalises the old rule that caught a missing measuring script by its historical filename: any script path either plan names must now exist or be declared in a fenced planned-artefacts block, which is what lets a reader tell "never written" from "not built yet". Both were mutation-tested, and one defect in this session's own work was caught by the project's guards rather than by review: the new test file wrote with `write_text(encoding=...)` and no explicit `newline=`, which encoding-guard reported as a WARN and which would have hard-failed close-out.
- 2026-08-27 - Inverted the review-baseline comparison in `run.py`, after the user restated the convention it encodes. It had asserted the baseline was byte-identical to its live document and failed otherwise, with a message reading "refresh before a review round". That is backwards: the baseline holds the version the reviewing AI last reviewed and is refreshed only once a review round has finished, so drift is the normal state for most of an item's life and is the diff the next review reads. Refreshing before a handover flattens it to nothing and makes the reviewer re-read the document blind. The comparison now lives in `compare_to_baseline`, reports drift as INFO with a real added/removed count, and fails only on a missing baseline, which is the one state with no diff surface at all. Two defects in the replacement were caught before it landed: a first version counted mismatched lines in lockstep and reported 1457 against a true 273, since one insertion shifts everything after it, and the docstring named the user in a tracked file, which the rule-hooks PreToolUse gate blocked rather than a reviewer catching later.
- 2026-08-27 - Narrowed a positive control in `run.py` that was broader than the claim it backed, which is the [[feedback_verify_the_checker]] fault rather than missing coverage. The three audit trails inside derived folders were asserted as "any of the three", so `session-search/data/LOG.md`, `knowledge-graph/index/LOG.md` and `web-research/outputs/LOG.md` could have gone from three to one in the selection with the check still reporting PASS; each is now asserted by path. Naming them costs nothing in brittleness, because they are fixed locations the workflows create and maintain, and nothing in privacy, because they are project paths rather than personal content. The related weakness in the same list, that "an authored personal folder contributes a non-markdown file" is satisfied by any single such file and so cannot prove the four authored folders take every file type, was deliberately not fixed here: narrowing it would mean naming a personal file in a tracked script, so it is proved by a fixture in the test suite instead. The new control was mutation-tested rather than trusted: pointing one of the three at a path that does not exist made the checker exit non-zero and print a FAIL section, and the mutation was reverted and the green result re-confirmed. Checker went from 30 PASS to 32.
